## Material not restored as active instructions

These decisions concern workflow requirements or incorrect examples, not the value of specialist knowledge:

- **Provider transcript upload:** `convex-improve-convex-plugin` is retained only in the original archive. Its procedure downloaded a shell helper from a provider endpoint and uploaded the current conversation after consent. No endpoint or helper was supplied with this repository. This separate provider-feedback operation is not needed for application maintenance. A future explicit feedback request must first establish the destination, inspect the actual helper and review what will be shared; this cleanup sends nothing.
- **Unavailable orchestration:** provider bootstrap helpers, Sentinel event loops, missing companion skills, required agent panels and fixed one-question-per-session limits are not active requirements. Their useful assessment, incident, decision and handoff procedures are in the destinations above.
- **Unrelated setup and promotion:** an existing Expo/Better Auth application must not be replaced with a Next.js scaffold, second auth provider or anonymous deployment merely to complete a task. Capability recipes remain available for a relevant request. They do not trigger automatic installation, promotion or deployment.
- **Incorrect or unnecessarily rigid examples:** the former C# pipeline omitted a routing operation and claimed exhaustiveness it did not establish. A compiled and exercised F# example replaces it. Quiz choices need comparable presentation, not identical character counts. Architecture and review findings require concrete evidence instead of quotas or mandatory output formats.
- **Repeated text and discovery assets:** duplicate host copies and repeated entry instructions use one source. Icons and agent metadata for removed duplicate entry points are in the archive; they contain no design or implementation guidance. Retained entry invocation policies remain in place.

Do not delete or split technical criteria, examples or procedures merely to reduce a skill's word count. Keep the normal task guidance in the skill body. Use named references when the material serves a distinct mode or optional need, and record substantive corrections separately. See the [context priorities](skill-inventory.md#context-priorities) for the selection and invocation criteria.
